Web 应急响应与 WAF 绕过

⭐ 一句话总结:Web 被入侵先做小溯源——从 Web 日志找到攻击载荷和对应代码漏洞并修复;WAF 绕过则围绕”身份认证→数据包解析→规则匹配”三层做文章。

学习目标

  • 掌握 Web 入侵排查与溯源
  • 了解网页挂马手法
  • 掌握 WAF 检测流程与绕过思路

一、Web 入侵排查

入侵路径:

  1. 系统层:开放端口(135/139/445)+ 未打补丁 → 系统漏洞入侵。
  2. 应用层:网站代码漏洞(SQL注入/XSS/上传等)→ 控制服务器。

排查要点:

  • 检查系统补丁(systeminfo + 官方公告对比)
  • 分析 Web 访问日志:找状态码 200、攻击 payload、命令执行回显
  • 定位请求对应代码文件 → 审计漏洞 → 修复
  • 查 WebShell 后门(地盾/河马)

二、溯源

  • 小溯源:找到攻击入口(哪个漏洞),修复它。
  • 大溯源:通过日志/IP 反向收集,找到攻击者本人(通常只能追到肉鸡/国外 VPS)。

蓝队溯源:结合安全设备报警日志 + 原始请求日志 + 全流量平台。

三、网页挂马

手法 说明
JS 挂马 页面插入 <script src="恶意JS">,访问即加载弹广告/木马
iframe 挂马 隐藏 iframe 嵌入恶意页面
主页篡改 修改首页代码跳转钓鱼页
变形加密 JS 混淆加密隐藏恶意代码

排查:检查 HTML 中异常 script/iframe 标签、响应包中的外链、文件修改时间。

四、WAF 检测流程

  • 规则库:URL/POST/Cookie/HTTP 头等位置的攻击特征。
  • 白名单放行、黑名单拦截;解析不了的数据交给服务器。

五、SQL 注入过 WAF(重点)

规则绕过

解析绕过

  • 编码(URL/base64/十六进制)、复参数、把载荷放 WAF 未检测的位置。

请求走私/分块传输

  • 请求头加 Transfer-Encoding: chunked,把请求体分块发送。
  • WAF 单块检测不到完整关键字,服务端重组后执行。
  • BP 插件 Chunked Coding Converter 一键分块。

⭐ 重点:绕过必须满足”WAF 不拦 + 数据库能执行”。

六、面试要点

过 WAF 常用手法:

  1. 白名单绕过(伪造搜索引擎 UA,较老)
  2. 数据包解析绕过(编码、复参数)
  3. 规则绕过(注释替换、拼接、大小写/双写、mod+in、&&/||、分块传输)

七、重点速记

  • Web 应急:日志找攻击载荷→定位代码→修复;系统补丁排查
  • 溯源:小溯源找入口,大溯源找人
  • 挂马:JS/iframe/主页篡改
  • WAF:黑白名单→解析→规则
  • 过 WAF:注释/**/、%0a、拼接、双写、mod+in、&&/||、chunked 分块

自测题

  1. Web 被入侵后小溯源做什么?
  2. 大溯源一般追到什么?
  3. 网页挂马常见手法?
  4. WAF 检测分哪几步?
  5. 空格被过滤怎么替换?
  6. 1=1 怎么替换?
  7. and/or 被拦截怎么办?
  8. 分块传输为什么能过 WAF?
  9. 过 WAF 的三大类思路?
  10. 从日志怎么判断攻击是否成功?
参考答案 1. 从日志定位攻击入口和对应漏洞并修复。
2. 肉鸡、国外VPS等,很难追到本人。
3. JS挂马、iframe挂马、主页篡改等。
4. 黑白名单、数据包解析、规则匹配。
5. /**/、%0a、括号等。
6. mod(8,7) in (1)。
7. 替换成 && 和 ||。
8. 数据分块发送,WAF逐块检测不到完整关键字,服务端重组执行。
9. 伪造白名单、解析绕过、规则绕过。
10. 看响应中是否包含payload执行结果、状态码200等。
