SQL 注入进阶

⭐ 一句话总结:不同数据库的注入大同小异,差别在”特性”——Access 靠暴力猜表,SQL Server 靠 SA/DBO 权限执行系统命令,MySQL 5.0+ 靠 information_schema;防护的核心是”不拼接、参数化、限权限”。

学习目标

  • 掌握 Access 数据库注入方式
  • 掌握 SQL Server 三大权限的利用
  • 理解 MySQL 5.0 上下版本和 MySQL8 的注入区别
  • 掌握 SQL 注入通用防护手段

一、Access 数据库注入

  • 特点:微软文档型数据库,一个 .mdb/.accdb 文件 = 一个库;没有库的概念,没有 information_schema。
  • 危害:如果通过目录扫描找到数据库文件路径,直接下载整个库。
  • 注入流程:
    1. 加单引号测注入点(报错即存在)。
    2. 用 exists(select * from 表名) 猜表名:报错=表不存在,不报错=表存在。
    3. 猜出表后猜列名(常见 admin、username、password),再 union select 1,2,3 找展示位,把列名填进去取数据。
  • 工具:穿山甲(Pangolin)、萝卜头,自动用内置字典猜表列。

二、SQL Server(MSSQL)注入基础

  • 默认端口 1433(Oracle 1521、MySQL 3306)。
  • 通用测试:' 报错、and 1=1 / and 1=2、order by N 判断列数(和 MySQL 不同,order by 后面是数字不是逗号列表)。
  • 联合查询时数据类型要求严格:字符串列放数字会报”类型转换失败”,把报错当回显用。
  • 系统信息函数:DB_NAME() 库名、@@VERSION 版本、USER_NAME() 用户、HOST_NAME() 主机名。
  • 取前 N 行用 select top 1 ...;跨库写法 库名..表名(如 master..sysobjects)。
  • 系统库 master 类似 MySQL 的 information_schema。

三、SQL Server 三大权限(重点)

权限 能力 利用重点
SA(sysadmin) 最高,可操作所有库 开启/使用 xp_cmdshell 执行系统命令
DB owner 只控制某个数据库 写一句话木马、备份数据库成木马文件
public 最低,只能查询 只能脱库,拿不到 shell

DB owner 权限注入

  • 判断:and 1=(select is_member('db_owner'))。
  • 拿 shell 方式一:xp_cmdshell 写一句话木马(需要先拿到站点真实物理路径)。
  • 拿物理路径:把 dir /s /b c:\目标文件 的执行结果 insert 进自建表,再通过报错注入读出来。
  • 拿 shell 方式二:把包含一句话木马的数据库备份成 .asp/.aspx 文件放到站点目录,再用菜刀/蚁剑连接。
  • 连接工具:菜刀(老)、蚁剑、冰蝎、哥斯拉;连上后权限 = Web 服务进程权限(如 IIS 的 IUSR),通常较低。

public 权限

  • 只能查数据:不断用报错/布尔方式提取库名(DB_NAME()/序号)、表名、列名、数据,即”脱库”。
  • 手工太慢可用穿山甲等工具;拿不到 WebShell。

四、MySQL 版本区别(面试题)

  • 5.0 及以上:自带 information_schema 库,直接查库/表/列。
  • 5.0 以下:没有该库,只能像 Access 一样暴力猜解。
  • 必记三张表:
表 关键字段
schemata schema_name(库名)
tables table_name(表名)、table_schema(库名)
columns column_name(列名)、table_name、table_schema
  • MySQL 8 与 5 的区别:
    • 创建用户和授权必须分两步(create user 后再 grant)。
    • 新增 table users(等价 select * from users)和 values row(1,2,3)(可替代部分 union select 场景)函数。

五、SQL 注入防护(报告必备)

  1. 类型判断:ID 参数必须是数字(is_numeric),非数字直接拒绝。
  2. 特殊字符转义:addslashes、mysql_real_escape_string,给引号加反斜杠。
  3. 正则过滤:禁止 union/and/or/select 等关键字。
  4. 参数化查询(重点):预处理 prepare + 参数绑定 bindParam,输入只当”值”不当 SQL 语句。
  5. 白名单过滤:动态表名/列名场景,只允许指定名称。
  6. 最小权限:网站连接数据库别用 root/SA,只授权所需库表的最小权限。
  7. 敏感数据加密:密码等用哈希(加盐)存储。
  8. 关闭错误显示:生产环境不向用户输出数据库报错信息。

⭐ 重点:防护总原则 = 永远不信任用户输入、永远不动态拼接 SQL、永远不用高权限连接数据库。

六、重点速记

  • Access:文件型数据库,exists 猜表 + union 取数,找到文件直接下载
  • MSSQL:1433 端口;order by 判断列数;类型转换报错=报错注入
  • SA→xp_cmdshell 建用户/开 3389;DBO→写马/备份拿 shell;public→只能脱库
  • MySQL:5.0+ 用 information_schema(schemata/tables/columns);8 分步授权+table/values
  • 防护:类型判断、转义、参数化查询、白名单、最小权限、加密、关报错

参考答案 1. Access 没有 information_schema,只能暴力猜表名列名,找到库文件还能直接下载。
2. 1433。
3. order by N 大于列数时报错,以此确定列数,方便 union select。
4. 通过 xp_cmdshell 执行系统命令,添加用户、开远程桌面、控制整台服务器。
5. SQL Server 的存储过程,可执行操作系统命令。
6. xp_cmdshell 写一句话木马;把含木马的数据库备份成 asp/aspx 文件。
7. 5.0+ 有 information_schema 可直接查结构,5.0- 只能暴力猜。
8. 预处理+参数绑定把输入当值处理,不会被拼成 SQL 语句执行。
9. 即使被注入或配置泄露,攻击者能操作的数据也有限。
10. 防止报错信息泄露数据库类型、表名、路径等敏感信息。
