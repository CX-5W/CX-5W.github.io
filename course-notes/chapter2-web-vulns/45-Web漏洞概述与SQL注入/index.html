Web 漏洞概述与 SQL 注入

⭐ 一句话总结:Web 渗透第一步是”对症下药”——先按 OWASP Top 10 和中间件/框架漏洞找方向;SQL 注入是经典注入漏洞,核心是”用户输入被拼进 SQL 语句”,再配合报错注入、联合查询、sqlmap 等手法把数据库数据拿回来。

学习目标

  • 掌握渗透测试阶段流程和 OWASP Top 10
  • 会寻找 SQL 注入点并判断注入类型
  • 掌握联合查询、报错注入、偏移量注入等手法
  • 理解加密注入、堆叠注入、中转注入、伪静态注入
  • 会用 sqlmap 自动化检测与取数

一、渗透测试阶段流程

  • 常规渗透:明确目标 → 信息收集 → 漏洞探测 → 漏洞验证 → 提取数据证明 → 信息分析 → 写报告。
  • 打点(授权攻击):发现漏洞后继续利用 → 提权 → 内网渗透。
  • 探测/验证分工具和手工:工具探测快但准度低,手工验证准(主流组合)。

二、优先关注哪些漏洞

  1. 中间件/框架漏洞(WebServer、CMS):先查信息收集到的版本,到漏洞库(如创宇 Seebug)搜 CVE 编号,找漏洞复现文章、POC、EXP。
    • POC = 漏洞检测脚本(证明有没有);EXP = 漏洞利用工具(直接拿权限)。
  2. 系统漏洞:一般只做版本+补丁核对,不主动打(容易打崩业务)。
  3. OWASP Top 10:Web 应用最危险漏洞排行。

三、OWASP Top 10(2021)

  1. 失效的访问控制(未登录/越权访问)
  2. 加密失败(敏感数据明文、弱加密)
  3. 注入(SQL/命令注入等,2017 前常年第一)
  4. 不安全的设计(架构设计缺陷)
  5. 安全配置错误(默认口令、目录浏览等)
  6. 易受攻击和过时的组件(老版本组件)
  7. 身份识别和认证失败
  8. 软件和数据完整性故障(反序列化等)
  9. 安全日志和监控失败
  10. 服务端请求伪造 SSRF

四、SQL 注入原理与寻找注入点

原理:程序把用户输入直接拼接进 SQL 语句,导致输入中的引号/关键字被当作 SQL 语法执行。

明显的注入点:登录、注册、搜索、留言板、评论、分页、排序、ID 参数。
隐藏注入点:Cookie、User-Agent、Referer 等一切可能被后端拿去查数据库的参数 → 抓包逐参数测试。

五、URL 编码与注释符

  • 键值对格式:键=值&键=值;值中出现特殊符号会被 URL 编码(%+ASCII 十六进制)。
  • GET 请求 URL 中不允许空格:用 + 或 %20 代替;# 需用 %23。
  • SQL 注释符:#(后不用空格)、-- (后必须有空格)。
  • POST 请求体中空格、井号可直接使用,不受 URL 限制。

七、联合查询注入

  • union select 要求前后列数一致,列数不一致会报错。
  • 用 select 1,2,3 补列;知道列数后把目标数据放在展示位上。

八、报错注入(重点)

适用:页面不回显查询结果,但会把数据库报错信息显示出来。

常用函数:

函数 作用
updatexml(1, concat(0x7e, 查询语句), 1) 用错误 XPath 触发报错
extractvalue(1, concat(0x7e, 查询语句)) 同上,查询型
floor(rand()*2) 取整,可制造主键冲突报错
concat() 字符串拼接,让报错信息完整
  • 0x7e 是 ~ 的十六进制,避免写引号冲突。
  • 常用内置信息:database() 库名、user() 用户、version() 版本。

十、偏移量注入

  • 适用:知道表名、不知道列名,且前面查询列数 > 后面查询列数。
  • 原理:union select 1,2,3... 补列,再用 select 1 from users 前后移动,让目标数据恰好落在页面展示的列上。
  • 条件苛刻、效果差,了解原理即可。

十一、其他注入手法

手法 要点
加密注入 数据被前端加密(如 Base64):先解密 → 加 payload → 用同样方式加密再发;可从 JS 找加密逻辑
堆叠注入 分号分隔多条 SQL:'; insert into ...; #,需要后端支持多语句
中转注入 自建中转页面/脚本转发请求,方便统一加 payload、编码、绕过设备
伪静态注入 URL 被 rewrite 成 .html 伪静态,注入点藏在伪静态路径参数中
二次注入 恶意数据先存库,再在另一处被拼进 SQL(如注册用户名注入)
宽字节注入 针对 addslashes 转义,用 %df' 吃掉反斜杠

十二、盲注概念

  • 页面无变化(无回显)≠没有注入点;可能被过滤,也可能注入成功但响应被加工。
  • 盲注手段:基于布尔(页面真假变化)、基于时间(延时判断)、报错被隐藏时用 DNSlog 外带。

十三、sqlmap 自动化工具

  • –os-shell 原理:先通过注入上传一个”文件上传功能”文件,再基于它上传真正的 WebShell 木马;木马通过 HTTP 收发命令(内部用 system/exec/passthru 等函数执行),结束会尝试自动删除文件。
  • 工具会大量发包:注意时间、线程数,别把目标打崩;抓包可以看到 sqlmap 的典型注入关键字。

十四、注入点利用思路

⭐ 重点:load_file() 读文件、into outfile 写文件是 SQL 注入 getshell 的两个关键功能。

十五、重点速记

  • OWASP Top10:访问控制、加密失败、注入排前三
  • 注入点:所有被拼进 SQL 的参数,包括 Cookie/UA
  • URL 编码:空格→+、#→%23;注释 # 和 –(带空格)
  • 联合查询要列数一致;报错注入用 updatexml/extractvalue + concat + limit
  • information_schema:库名→表名→列名→数据
  • 加密/堆叠/中转/伪静态/二次/宽字节注入各有场景
  • sqlmap:-r 数据包、–level/–risk、–dbs/–tables/–dump、–os-shell

参考答案 1. 失效的访问控制。
2. 加单引号看是否报语法错误,再用 or 1=1 / or 1=2 对比响应。
3. URL 中不允许空格,浏览器自动 URL 编码,空格编码为 + 或 %20。
4. # 后面不用空格,-- 后面必须有空格。
5. 前后查询的列数必须一致,可用 1,2,3 补列。
6. updatexml、extractvalue、floor;concat 不能拼接多行,用 limit 逐条取。

8. -r 用抓包数据包文件,-u 直接指定 GET 网址。
