50 · CSRF跨站请求伪造

CSRF 跨站请求伪造

⭐ 一句话总结:CSRF 利用”浏览器会自动携带 Cookie”的特性,让已登录用户在不知情时向目标网站发出恶意请求——改密码、加管理员、拖库都能干;Referer、Token、原密码是三层防线。

学习目标

  • 理解 CSRF 原理与两个前提
  • 掌握 GET/POST 型 CSRF 利用
  • 会手工检测 CSRF 漏洞
  • 理解 Token/Referer 防御与绕过
  • 了解 XSS+CSRF 组合攻击

一、CSRF 是什么

  • 全称 Cross-Site Request Forgery(跨站请求伪造),又称 One-Click 攻击(点击攻击)。
  • 原理:
  • 危害大且隐蔽,被称为”沉睡的巨人”。

二、两个前提

  1. 用户已登录目标网站(建立了会话,浏览器有 Cookie)。
  2. 触发浏览器自动发请求(恶意页面/图片/链接/自解压包)。

三、分类

类型 说明
站外攻击 恶意网站/第三方页面触发请求
站内攻击 目标网站自身漏洞(如存储型 XSS)植入触发代码

四、利用方式

1. GET 型 CSRF

2. POST 型 CSRF

诱导受害者打开页面并点击提交(或 JS 自动 submit)。

3. 自解压压缩包

  • 压缩时设置”解压后运行”为恶意网址,受害者解压即自动打开浏览器访问。

4. 真实案例(脱库)

  • Discuz 后台数据库备份是 GET 请求:在评论里插入 <img src="备份URL&备份目录&文件名">,管理员查看帖子时自动触发备份,攻击者再直接下载生成的 .sql 文件。
  • 复杂利用常来自代码审计(拿到开源 CMS 源码分析请求结构)。

五、手工检测方法

  • 抓取提交数据的数据包(修改密码、添加用户等)。
  • 删除 Referer 字段再放行:如果操作成功 → 存在 CSRF 漏洞。

六、防御与绕过

防御 说明 绕过
Referer 校验 检查来源域名 让恶意页面 URL 包含目标 host(文件名/目录/参数伪造)
CSRF Token 页面隐藏 token + 服务端 session 对比 先发前置请求拿 token 再替换(工具:BP 插件 CSRF Token Tracker)
原密码/验证码 修改密码需输原密码 基本无法绕过(最有效)
严格区分 GET/POST 不用 $_REQUEST 万能取值 减少攻击面
安全设备 WAF 等检查请求 可缓解

⭐ 重点:Token 一次一换,放在隐藏 input 或自定义请求头;绕过思路 = 先请求页面提取 token,再带入下一个请求。

七、XSS + CSRF 组合

  • 场景:HttpOnly 拿不到 Cookie,但站点有存储型 XSS。
  • 打法:存储型 XSS 中写入跳转/加载代码,受害者一访问即触发 CSRF(如自动打开改密 POC 页面)。
  • 结果:受害者密码被改,攻击者用新密码登录。

八、工具

  • BP 生成 CSRF POC:右键数据包 → 相关工具 → 生成 CSRF POC(自动生成 form 页面)。
  • CSRF Tester:半自动化,抓流量 → 改参数 → 生成多种 POC(表单/iframe/img/ajax/链接)。

九、重点速记

  • CSRF = 借用户之手发请求;前提:已登录 + 触发
  • GET 型:img/a 标签;POST 型:伪造表单
  • 检测:删 Referer 放行,成功即有漏洞
  • 防御:Referer + Token + 原密码/验证码
  • 绕过:伪造 Referer、前置取 Token
  • XSS+CSRF 可组合改密、加管理员、拖库

自测题

  1. CSRF 攻击需要哪两个前提?
  2. 为什么浏览器会自动携带 Cookie?
  3. GET 型和 POST 型 CSRF 有什么区别?
  4. 手工检测 CSRF 最简单的方法?
  5. CSRF Token 为什么能防 CSRF?
  6. Token 怎么绕过?
  7. 修改密码最有效的防御是什么?
  8. XSS 和 CSRF 怎么组合?
  9. 自解压包为什么能攻击?
  10. Referer 校验怎么绕过?
参考答案 1. 用户已登录目标站且浏览器被触发自动发请求。
2. 浏览器机制:访问同一站点会自动带上该站点 Cookie。
3. GET 用 img/a 标签即可触发,POST 需伪造表单并诱导提交。
4. 抓包删掉 Referer 再放行,操作成功即有漏洞。
5. 服务端生成随机 token 放入页面,提交时对比;自动请求无法携带页面里的 token。
6. 先请求页面提取 token,再把它替换进下一个请求(可工具化)。
7. 修改密码必须输入原密码或验证码。
8. 用存储型 XSS 触发 CSRF,受害者访问页面即被改密。
9. 解压时自动运行恶意网址,浏览器自动发起请求。
10. 让恶意页面 URL 中带上目标 host,使 Referer 包含目标域名。
