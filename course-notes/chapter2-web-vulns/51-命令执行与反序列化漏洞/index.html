51 · 命令执行与反序列化漏洞

命令执行与反序列化漏洞

⭐ 一句话总结:命令执行漏洞让你在服务器上”敲命令”,反序列化漏洞让你通过一段字符串”唤醒恶意代码”——两者都常出现在框架/中间件中,影响范围通常是一大片使用相同版本的网站。

学习目标

  • 区分远程命令执行与远程代码执行
  • 掌握命令连接符和注入方式
  • 理解序列化/反序列化原理
  • 理解反序列化漏洞的触发链
  • 了解常见框架 RCE/反序列化漏洞

一、RCE 概念

类型 含义 例子
远程命令执行 执行系统指令 ipconfig、net user
远程代码执行 执行后端语言代码 PHP eval()、Java 表达式

常见出现位置:运维自动化平台、ping 检测、执行命令的后台功能、框架漏洞。

二、命令注入

后台把用户输入拼进命令执行函数:

命令连接符:

符号 效果
; 无条件执行多条命令
& 前后都执行
&& 前面成功才执行后面
| 前面输出作为后面输入
|| 前面失败才执行后面

利用示例:添加系统用户 & net user hacker 123 /add & net localgroup administrators hacker /add。

三、命令注入绕过

  • 过滤 && 就试 &、;、|、||。
  • 过滤空格:用 ${IFS}、%09(Tab)、去掉空格等。
  • 过滤关键字:变量拼接(w+h+o+a+m+i)、编码等。
  • 结论:过滤不严谨(如只替换一次)都能绕过,所以要逐字符测试。

四、框架漏洞与 RCE

  • 中间件/框架版本漏洞常导致 RCE:Struts2(S2-045/048/052/057)、WebLogic、Fastjson、Shiro、Spring、Redis 未授权、OA 系统(致远/蓝凌/泛微)等。
  • 利用方式:找 POC/EXP 或综合利用工具直接打;到 Seebug/Freebuf 等平台搜漏洞复现过程。
  • 检测:信息收集确认版本 → 找对应 POC → 复现/利用 → 截图证明。

五、序列化与反序列化

  • 序列化:把对象/数组等数据转成字符串(便于存储、传输、跨语言)。
  • 反序列化:把字符串还原成对象/数据。
  • 格式含义:O 对象、类名长度、属性名/值及长度等。

六、反序列化漏洞原理(重点)

  1. 攻击者构造恶意序列化字符串(类里定义魔术方法,如 __destruct 中写命令执行代码)。
  2. 目标程序对用户可控数据直接 unserialize()。
  3. 反序列化生成对象后,对象销毁时 __destruct 自动触发 → 恶意代码执行。

⭐ 重点:漏洞链 = 用户可控数据 + 未过滤反序列化 + 魔术方法自动触发。

  • 特点:黑盒很难发现,大多通过代码审计或框架公开漏洞发现。
  • 典型案例:WebLogic T3、Fastjson、Shiro、PHP 框架(Laravel 等)反序列化漏洞。

七、中间件/框架/Web 服务程序区分

  • Web 服务应用程序:接收并转发请求(Apache、Nginx、IIS、Tomcat、WebLogic)。
  • 框架:加工处理请求数据、封装公共功能(Struts2、Spring、Laravel、Django)。
  • 中间件:以上统称(客户端与最终数据之间的一切程序)。

八、利用与检测思路

  • 反序列化漏洞:确认指纹(WebLogic 7001 端口等) → 用综合利用工具检测/执行命令 → 截图证明。
  • 检测命令执行:在参数后加连接符+命令,看回显。

九、重点速记

  • RCE = 命令执行(系统指令)/代码执行(语言代码)
  • 命令连接符:; & && | ||
  • 绕过:换符号、去空格、变量拼接
  • 序列化转字符串,反序列化还原对象
  • 反序列化漏洞 = 可控数据 + unserialize + 魔术方法自动执行
  • 框架漏洞影响面大;新漏洞关注 Seebug/Freebuf

自测题

  1. 远程命令执行和远程代码执行的区别?
  2. 命令连接符有哪些?&& 和 ; 的区别?
  3. 命令注入怎么测?
  4. 过滤了 && 怎么绕过?
  5. 序列化和反序列化是干什么的?
  6. 反序列化漏洞的触发链是什么?
  7. 魔术方法 __destruct 什么时候执行?
  8. 为什么框架反序列化漏洞影响面大?
  9. Web 服务程序和框架有什么区别?
  10. 反序列化漏洞为什么难在黑盒中发现?
参考答案 1. 命令执行执行系统指令,代码执行执行后端语言代码。
2. ; & && | ||;&& 前面成功才执行后面,; 无条件都执行。
3. 在参数后加连接符和命令看回显,如 & whoami。
4. 换用 &、;、|、|| 或编码绕过。
5. 序列化把数据转成字符串,反序列化把字符串还原成数据。
6. 用户可控数据 → 直接 unserialize → 魔术方法自动执行恶意代码。
7. 对象被销毁时自动触发。
8. 同一框架/版本被大量网站使用,一个漏洞通杀一片。
9. Web 服务程序接收转发请求,框架加工请求数据并封装功能。
10. 需要看源码确认反序列化点和过滤情况,多靠代码审计。
