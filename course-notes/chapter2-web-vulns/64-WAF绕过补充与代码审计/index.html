WAF 绕过补充与代码审计

⭐ 一句话总结:WAF 绕过按”身份认证→解析→规则”三层推进,工具用 sqlmap –tamper;代码审计(白盒)则是拿着源码按”危险函数关键字”和”业务流程”两条思路找漏洞。

学习目标

  • 系统掌握 WAF 绕过三类手法
  • 会用 sqlmap tamper 过 WAF
  • 理解代码审计思路与方法
  • 会用工具+手工验证审计结果

一、WAF 绕过体系(补充)

1. 身份认证阶段

  • 伪造搜索引擎 UA(Baiduspider/Googlebot,较老)
  • 伪造白名单目录/域名
  • 找真实 IP 绕云 WAF

2. 数据包解析阶段

  • 编码:URL、base64、Unicode
  • 请求方法绕过(get→post)
  • 请求数据位置绕过(注入放 WAF 未检测的请求头等)
  • 复参数绕过(id=1 and id=union and id=select)

3. 规则匹配阶段

  • 特殊字符替换空格:/**/、%0a
  • 字符串拼接:concat('un','ion')、加号
  • 注释包含关键字:/*!50000union select*/
  • 大小写、双写
  • 编码+注释组合
  • 变量/函数替换:1=1 → mod(8,7) in (1)
  • and → &&,or → ||
  • 分块传输(chunked)

二、文件上传过 WAF

  • filename 前加 \x09
  • 去掉 filename 双引号
  • 添加多个 filename 参数
  • form-data 用加号拼接/去掉 form-data
  • 后缀大小写、空格点等

三、sqlmap 过 WAF

  • --tamper 指定 python 文件对 payload 加工(大小写、编码等)。
  • 内置 tamper 多已被 WAF 规则收录,可自己写 python 规则。
  • 配合 --delay 控制发包速度。

四、WAF 识别

  • wafw00f(Kali 内置)
  • identify-waf(sqlmap 已集成)
  • 原理:发探测请求,用响应特征匹配 WAF 指纹。

五、代码审计(白盒测试)

两种思路

  1. 关键字定位:按危险函数找代码位置。
漏洞 关键字
文件包含 include、include_once、require
命令执行 eval、system、exec、shell_exec
SQL注入 select/insert/update、$_GET/$_POST/$_REQUEST
反序列化 unserialize
  1. 业务流程跟踪:从入口文件(如 index.php)开始,跟随用户输入走到哪里、有没有过滤。

查看配置文件

  • config/conn 等文件:数据库连接、路径配置。
  • 定位数据流向,看输入是否被过滤。

漏洞成因

  • 变量控制不严 + 使用了功能强大的危险函数。

六、审计工具

  • Seay 源代码审计系统(免费,专审 PHP,按危险函数扫描)
  • Fortify SCA(商业,支持多语言)
  • 工具局限:误报漏报多,必须人工甄别,最终要部署代码+渗透验证。

七、案例(熊海CMS)

  • 审计发现 index.php 中 include($file.".php"),参数 R 可控且无过滤。
  • 手工验证:?r=../1 目录穿越读取上级 PHP 文件 → 任意文件包含漏洞。
  • 流程:代码审计定位 → 搭建环境 → 渗透复现 → 确认漏洞。

八、目录遍历漏洞

  • Web 服务器开启了目录浏览(index of),任意目录文件可被列举。
  • 配置不当导致,修复:关闭目录浏览。

九、重点速记

  • 过 WAF:白名单/解析/规则三层
  • sqlmap –tamper 自写规则
  • 代码审计=白盒;关键字定位+业务流程
  • 危险函数:include/eval/system/unserialize
  • 工具:Seay、Fortify;结果需人工+实战验证
  • 目录遍历=目录浏览配置不当

自测题

  1. WAF 绕过分哪三个层面?
  2. 复参数绕过是什么?
  3. sqlmap 过 WAF 用什么参数?
  4. 为什么内置 tamper 可能失效?
  5. 代码审计的两种思路?
  6. 文件包含漏洞审计找什么关键字?
  7. 命令执行审计找什么函数?
  8. 代码审计为什么要做渗透验证?
  9. 目录遍历漏洞是什么原因?
  10. 审计工具主要局限是什么?
参考答案 1. 身份认证、数据包解析、规则匹配。
2. 把 union/select 等拆成多个参数,让WAF看不到完整语句。
3. --tamper 指定python规则文件,可配合--delay。
4. 内置tamper已被各WAF规则库收录。
5. 危险函数关键字定位、入口文件业务流程跟踪。
6. include、include_once、require。
7. eval、system、exec、shell_exec。
8. 代码审计结论可能有误报,需实际部署复现确认。
9. Web服务器开启了目录浏览功能。
10. 误报漏报多,需大量人工甄别。
