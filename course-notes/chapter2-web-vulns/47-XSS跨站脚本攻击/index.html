47 · XSS跨站脚本攻击

XSS 跨站脚本攻击

⭐ 一句话总结:XSS 是把恶意 JS 代码”存进”页面,让别人的浏览器执行——攻击对象是用户不是服务器;危害集中在盗 Cookie、窃密码、钓鱼,存储型最危险,HttpOnly 和输出编码是主要防线。

学习目标

  • 理解 XSS 原理与三大分类
  • 会找输入输出点并构造 payload
  • 掌握 Cookie 窃取、钓鱼等利用方式
  • 掌握常见过滤绕过手段
  • 理解 HttpOnly、同源策略与跨域

一、XSS 是什么

  • 全称 Cross-Site Scripting(跨站脚本攻击),因缩写与 CSS 冲突,改名 XSS。
  • OWASP Top 10 常客,2021 年排第三,被归类为注入攻击。
  • 攻击的是客户端(浏览器/APP 用户),不是服务器。
  • 载体:JavaScript(还有 ActionScript、VBScript 等浏览器可解析的脚本)。

二、原理与产生条件

产生条件(缺一不可):

  1. 有输入:用户数据能提交到服务端(评论、搜索、用户名等)。
  2. 有输出:该数据被服务端回显到页面上。

三、危害

  • 窃取 Cookie/Session(会话劫持,以受害者身份登录)
  • 窃取用户名密码、浏览器保存的密码
  • 键盘记录、钓鱼弹框
  • 配合 CSRF 操作受害者账号

⭐ 重点:危害上限 = 攻击者写的 JS 能力上限。

四、三大分类

类型 特点 危害
反射型 参数带在 URL 中,不存储 需诱导用户点击构造链接
存储型 恶意代码存入数据库,所有人访问都触发 高危
DOM 型 JS 操作 DOM 产生,一般不与服务端交互 中低危,但可结合反射型利用

五、寻找与测试

  • 找”有输入 + 有输出”的位置:搜索框、留言板、用户名回显、Referer/UA/Cookie 回显等。
  • 基础 payload:
  • 属性位置注入:用引号闭合前面的属性,再添加 on* 事件。
  • 判断是否成功:弹框出现,或 BP 响应中输出内容被当作标签解析。

六、DOM XSS

  • 危险操作:innerHTML、document.write、location、document.referrer 等把数据写进页面。
  • 测试:闭合外层属性后添加事件,如 " onmouseover=alert(1)。
  • 典型示例:输入被拼进 <a href="输入">,用 " onclick=alert(1) 闭合绕过。

七、利用实战

1. 窃取 Cookie(会话劫持)

拿到 Cookie 后:用 BP 把请求中的 Cookie 替换为目标用户 Cookie → 直接以对方身份访问。

2. 反射型 POST 场景

  • POST 型反射 XSS 需要伪造 HTML 页面:表单 action 指向目标漏洞页,window.onload 自动提交表单,表单里带上恶意 payload。
  • 诱导受害者打开该页面,浏览器自动完成”提交 → 反射 → 执行 → 盗 Cookie”。

3. 钓鱼弹框

  • 在存储型 XSS 中注入弹框代码(伪造登录框),受害者输入用户名密码后被发送到攻击者服务器。
  • 其他钓鱼:伪造相似域名网站、邮件钓鱼、iframe 嵌入等。

八、绕过技巧(重点)

过滤方式 绕过
只过滤小写 script 大小写混合 <ScRiPt>
str_replace 只替换一次 双写 <scr<script>ipt>
过滤 script 标签 换标签 <img onerror>、<svg onload>、<a href=javascript:>
htmlspecialchars 默认参数 用单引号闭合属性(默认不编码单引号,需加 ENT_QUOTES)
过滤空格 用换行符 %0a 或 / 代替空格
输出在 JS 中 闭合前面引号/script 标签后自己写 <script>
实体编码防御 若输出在属性值且单引号未被编码,可属性闭合绕过
  • JS 编码:\u0061 等;HTML 实体编码:&#x3c;、&lt; 等——编码能否生效取决于最终由哪个解析器处理。

⭐ 重点:绕过要满足两个条件——① 绕过服务端过滤;② 浏览器最终能解析执行。两者缺一不可。

九、XSS 防范

  1. 输入过滤:过滤 <、>、引号等特殊字符。
  2. 输出编码:输出到 HTML 时用 htmlspecialchars(数据, ENT_QUOTES) 编码尖括号和引号。
  3. Cookie 设置 HttpOnly:JS 无法读取 document.cookie,防止盗 Cookie。
  4. CSP(内容安全策略):限制可执行的脚本来源。
  5. 框架自带转义:Vue/React 等默认转义输出。

十、HttpOnly 与绕过

  • HttpOnly=true 表示 Cookie 只允许 HTTP 传输,document.cookie 读不到。
  • 绕过思路:放弃 Cookie,转而窃取用户名密码——表单劫持(登录页注入伪登录框)、读取浏览器保存的密码。
  • 安全意识:浏览器不要保存密码,别乱打开陌生 HTML/链接。

十一、同源策略与跨域

  • 同源:协议 + 域名 + 端口都相同;非同源页面不能互相读取数据。
  • 浏览器拦截的是响应,请求本身会发出去(因此”发数据盗 Cookie”可用)。
  • 跨域方式:
    • CORS:服务端返回 Access-Control-Allow-Origin 允许指定域名访问。
    • JSONP:利用 <script src> 跨域特性,携带 callback 参数,服务端返回 callback(数据)。
    • 标签跨域:script、img、link、iframe、a 五大标签默认支持跨域(iframe 嵌入别人页面可做挂马/钓鱼)。

十二、XSS Labs 靶场思路

  • 第 1 关:无过滤,直接 <script>alert(1)</script>。
  • 第 2 关:输出在 input value,闭合属性:"><script>alert(1)</script>。
  • 第 3 关:htmlspecialchars 但没编码单引号 → 用单引号闭合。
  • 第 11/12/13 关:输出点分别是 Referer、User-Agent、Cookie → 抓包改对应请求头注入。
  • 第 15 关:AngularJS ng-include 引入外部页面,利用被引入页面的 XSS。
  • 第 16 关:过滤空格 → 用换行符 %0a 绕过。
  • 第 17/18 关:输出在 embed 标签属性 → 闭合属性加 onmouseover 事件。
  • 第 19/20 关:Flash 触发,技术已废弃。

十三、重点速记

  • XSS=攻击客户端;输入+输出缺一不可
  • 反射型不存储、存储型最高危、DOM 型操作页面
  • 盗 Cookie:document.location 带 document.cookie;换 Cookie 即会话劫持
  • 绕过:大小写、双写、换标签、单引号闭合、换行符、JS 编码
  • 防御:输入过滤+输出编码+HttpOnly+CSP
  • 同源三要素:协议/域名/端口;CORS/JSONP/标签跨域

  4. 如何判断一个输入点是否存在 XSS?
  5. 为什么存储型 XSS 危害最大?
  6. 拿到别人 Cookie 后怎么登录?
  7. HttpOnly 能防 XSS 吗?它防什么?
  8. 列出三种 XSS 绕过方式。
  9. 同源策略中的”同源”指什么?
  10. JSONP 为什么能跨域?
参考答案 1. 客户端(浏览器/APP 用户)。
2. 有输入且输入被输出到页面。
3. 反射型参数在 URL 不存储,存储型存入数据库,DOM 型由 JS 操作 DOM 产生。
4. 提交 或事件类 payload,浏览器弹框即存在。
5. 一次写入,所有访问该页面的用户都会触发。
6. 抓包后把请求中的 Cookie 替换成目标用户的 Cookie 再发送。
7. 不能防 XSS,只防 JS 通过 document.cookie 读取 Cookie。
8. 大小写混合、双写绕过、换标签/单引号闭合属性等。
9. 协议、域名、端口都相同。
10. 利用 script 标签 src 默认支持跨域,服务端返回回调函数调用。
