Nginx 基础与 HTTP 协议

⭐ 一句话总结:Nginx 是当下最主流的 Web 服务器(低资源、高并发),靠配置文件控制站点;HTTP 协议就是”请求四段、响应四段”的格式约定——渗透测试天天和它打交道。

学习目标

  • 了解常见 Web 服务器(Apache/Nginx/Tomcat/IIS)
  • 看懂 Nginx 主配置(worker、server、location)
  • 会用 nginx -t 检查配置、重启服务
  • 掌握 HTTP 请求/响应格式和常见状态码

一、Web 服务器有哪些

软件 特点
Apache(HTTPD) 最早、最著名,Apache 基金会旗下
Nginx 后起之秀,俄罗斯人开发,低资源高并发(上万并发),现在主流
Tomcat Java 项目常用(后面讲)
IIS Windows 专用
  • Web 服务器 = 承接请求、转发给网站代码、返回响应;真正干活的是网站代码。

二、Nginx 进程模型

  • master 主进程(管理进程):领导,负责管理 worker;删了它 Nginx 就停。
  • worker 工作进程:真正干活的工人,被杀掉后 master 会自动重启一个。
  • 配置 worker_processes 1:启动几个 worker,一般设成 CPU 核数(8 核设 8),不是越大越好(吃内存)。
  • worker_connections 1024:每个 worker 最大并发连接数。

⭐ 重点:

  • 网址路径 ↔ 物理路径映射:访问 http://IP/images/a.jpg 就是找站点根目录下的 images/a.jpg。
  • 站点目录没有 index.html 会报 403 Forbidden。
  • 改了监听端口(如 8081),访问必须写端口 http://IP:8081。
  • 一个服务器可同时跑多个 Web 服务/多个站点,只要端口不冲突。

四、mime.types 文件类型

  • 定义 Nginx 认识的文件类型(html、css、图片、mp4 等)。
  • 交互效果:Nginx 认识、浏览器不认识 → 浏览器按文本打开(乱码);两边都不认识 → 直接下载;浏览器认识 → 正常显示。

五、HTTP 协议

  • HTTP = 超文本传输协议,1990 年由蒂姆·伯纳斯-李发明(比 Linux 内核还早);应用层协议。
  • 每次交互 = 客户端发请求,服务端回响应。

请求格式(四部分)

  • GET:向服务端要数据;参数拼在 URL 里。
  • POST:向服务端提交数据(登录、搜索、评论),数据放在请求体。
  • URL = 完整网址(协议+主机+端口+路径);URI = 路径部分(/images/a.jpg)。

响应格式(四部分)

⭐ 重点:状态码 200 = OK;304 = 用缓存;403 = 禁止访问;404 = 找不到;500 = 服务器内部错误。Wireshark 抓 HTTP 包可”追踪 HTTP 流”直接看明文请求/响应。

六、重点速记

  • Nginx:master 管 worker,worker 干请求;worker_processes = CPU 核数
  • 配置:listen 端口、server_name 域名、root 站点根目录、index 默认页
  • 改配置先 nginx -t,再 systemctl restart nginx
  • 无 index.html → 403;改端口要带端口访问
  • HTTP 请求:请求行+请求头+空行+请求体;响应:响应行+响应头+空行+响应体
  • GET 拿数据、POST 交数据;200/304/403/404/500

自测题

  1. Nginx 的 master 进程和 worker 进程是什么关系?
  2. worker_processes 一般设置多少?
  3. 站点根目录用什么配置项?默认首页文件叫什么?
  4. 访问网站报 403 是什么原因?
  5. HTTP 请求由哪四部分组成?GET 和 POST 的区别?
  6. URL 和 URI 的区别?
  7. 状态码 200、304、403、404、500 分别表示什么?
  8. 修改 Nginx 配置后怎么检查语法和重启?
参考答案 1. master 是管理进程,worker 是干活的;worker 挂了 master 会重启它,master 挂了服务停。
2. 和 CPU 核数一致。
3. root;index.html。
4. 站点目录里没有 index.html 或没有访问权限。
5. 请求行、请求头、空行、请求体;GET 拿数据,POST 提交数据。
6. URL 是完整网址,URI 是其中的路径部分。
7. 成功/缓存/禁止/找不到/服务器错误。
8. nginx -t;systemctl restart nginx。
