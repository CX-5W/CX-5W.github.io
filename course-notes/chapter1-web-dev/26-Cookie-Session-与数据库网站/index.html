26 · Cookie/Session 与数据库网站

Cookie/Session 与数据库网站

⭐ 一句话总结:HTTP 无状态,登录状态靠 Cookie(存客户端)/Session(存服务端)维持;动态网站 = 前端 + 后端语言 + Web 服务器 + 数据库;渗透测试就是从这些组件里找突破口。

学习目标

  • 理解 Cookie 与 Session 的原理和区别
  • 记住常见网站架构(LNMP/LAMP 等)
  • 会 MySQL 基本操作、创建库/用户/授权
  • 会部署 WordPress、Discuz(PHP + MySQL)
  • 理解静态、动态、伪静态页面

一、为什么需要 Cookie / Session

  • HTTP 是无状态协议:不记录登录状态,每次请求都是”陌生人”。
  • 解决:登录成功后,服务端发一个”身份令牌”,下次请求带上它,服务端就知道你是谁。

Cookie(存在客户端)

  1. 登录 → 服务端在响应头里返回 Set-Cookie(键值对,如 username=jadon)。
  2. 浏览器自动保存到本地缓存,下次请求自动携带(请求头 Cookie)。
  3. 缺点:存在客户端、明文、能存的数据少(约 30 组键值对)、数据量大影响速度。

Session(存在服务端)

  1. 登录成功 → 服务端把用户数据加密保存到服务端文件,只把 Session ID(随机字符串)通过 Set-Cookie 发给客户端。
  2. 客户端再请求时带上 Session ID,服务端据此找到对应数据。
  3. 优点:数据在服务端(想存多少存多少)、客户端只有一把”钥匙”、不是明文。

⭐ 重点:客户端删 Cookie = 退出登录;服务端删 Session 文件 = 也退出。偷到别人的 Cookie/Session ID 就能冒充登录状态——这是后面会话攻击的基础。

二、网站架构

架构 组成 跑什么项目
LNMP Linux + Nginx + MySQL + PHP PHP 网站
LAMP Linux + Apache + MySQL + PHP PHP 网站(早期经典)
WAMP Windows + Apache + MySQL + PHP Windows 下 PHP
LNMT Linux + Nginx + MySQL + Tomcat Java 项目
LNMU Linux + Nginx + MySQL + UWSGI Python 项目
  • 中间件 = Web 服务器(Nginx/Apache/Tomcat);数据库存数据(MySQL 等)。
  • 渗透时先判断架构,就知道从哪下手(如 LNMP → 打 PHP + MySQL)。

三、MySQL 数据库基础

  • MySQL = 数据库管理系统(DBMS);开源免费,后被 Oracle 收购;创始人另立 MariaDB(几乎一样)。
  • 结构:库 → 表 → 记录(行),表第一行是列名。
  • 安装:yum install -y mariadb-server,启动后监听 3306 端口。

创建用户并授权(一条指令):

  • 库名.* = 该库所有表;'用户'@'主机' 控制从哪连(本地用 localhost/主机名,远程用 IP 段或 %)。
  • 连接:mysql -u用户 -p密码 -h主机IP。
  • ⚠️ 删库跑路要判刑:删除操作必须万分小心,公司数据损失可能上千万。

扩充:图形化客户端 Navicat(可连接远程 MySQL);密码在库里是加密存储的(如 MD5),可尝试在线破解。

四、部署动态网站:WordPress 与 Discuz

WordPress(博客,CMS 内容管理系统)

  1. 建库建用户(如 wordpress/123456)→ Nginx 加站点配置(域名+root+PHP 转发)→ 代码放站点目录,chown -R nginx:nginx。
  2. 浏览器访问 → 填写数据库名/用户名/密码 → 设置站点名、后台管理员账号密码 → 完成。
  3. 结构:前台(给游客看文章)+ 后台(管理文章/评论/插件)。
  4. 概念:百度收录/SEO:网站上线后百度抓取页面存库,用户搜索能搜到;”禁止搜索引擎检索”可关掉收录。

Discuz(论坛)

  • 同样 PHP + MySQL;建 discuz 库/用户 → 部署 → 初始化(选全新安装 + UCenter 后台)。
  • 后台可建板块、发帖、投票;很多国内论坛(吾爱破解、恩山等)都是它改的。

五、静态 / 动态 / 伪静态页面

类型 特点 安全/速度
静态 每个 URL 对应一个 HTML 文件,内容固定 安全、快、方便 SEO
动态 一个 PHP 文件 + 参数查数据库,数据因人而异 有交互,容易被攻击、较慢
伪静态 动态页面”伪装”成 .html 网址(底层还是动态) 看着像静态,实际仍是动态
  • 伪静态实现:Discuz 后台开启”URL 静态化” → Nginx 配置里加 rewrite 规则(正则把 .html 路径转回 .php?参数)。
  • 好处:防小白误以为可攻击 + 利于 SEO;代价:多一次转换,速度略慢。

⭐ 重点:动态页面能交互 = 攻击面(用户可提交恶意数据);渗透测试主要打动态部分。

六、重点速记

  • HTTP 无状态;Cookie 存客户端(明文、量小),Session 存服务端(加密,只发 Session ID)
  • 删 Cookie/清 Session = 退出登录;偷到 Session ID 可冒充登录
  • 架构:LNMP/LAMP/LNMT/LNMU;中间件 + 数据库 + 开发语言
  • MySQL:库→表→记录;3306;grant 授权;删库危险
  • WordPress/Discuz 都是 PHP+MySQL 的 CMS;前台给用户、后台给管理
  • 伪静态 = rewrite 把动态 URL 伪装成 .html

参考答案 1. HTTP 无状态不记录登录,需要 Cookie 记住登录身份。
2. Cookie 存在客户端(明文),Session 数据存在服务端,客户端只有 Session ID。
3. 服务端认为你未登录,要求重新登录。
4. Linux+Nginx+MySQL+PHP;Linux+Nginx+MySQL+Tomcat(Java)。
5. 库包含多张表,表由多行记录组成。
6. `grant all on 库名.* to '用户'@'主机' identified by '密码';`。
7. CMS 内容管理系统(博客/论坛);需要 Nginx+PHP+MySQL+网站源码。
8. 把动态 URL(带 ? 参数)用 rewrite 规则伪装成 .html,底层仍是动态处理。
