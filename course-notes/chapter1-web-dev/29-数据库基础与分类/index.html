29 · 数据库基础与分类

数据库基础与分类

⭐ 一句话总结:数据库管理系统(DBMS)是专门高效存取数据的软件,关系型存”有关联”的数据,非关系型存”量大但没啥关联”的数据;网站数据基本都存在这里——渗透测试迟早要打它。

学习目标

  • 理解数据库/DBMS/SQL 的概念
  • 分清关系型与非关系型数据库
  • 认识主流数据库(Oracle/MySQL/MariaDB/SQL Server/Redis/MongoDB)
  • 会安装 MariaDB、基本库/表操作、授权

一、什么是数据库

  • 数据库:专门存储数据的地方;DBMS(数据库管理系统):管理这些数据的软件(如 MySQL)。
  • 记事本/Word 不适合网站数据:打开慢、无法精准取一条数据、不支持大量并发。
  • SQL(结构化查询语言):客户端发给数据库服务端的操作指令(查询/增删改)。
  • 架构:CS 架构——数据库服务端(3306 端口)+ 客户端(命令行/图形化/Navicat/网站代码)。

二、关系型数据库(RDBMS)

  • 数据像 Excel 表格:库 → 表 → 列(字段)→ 行(记录)。
  • 优点:能建立数据关联(学生表 ↔ 班级表 ↔ 老师表),查询处理方便。
  • 常见:
数据库 特点
Oracle 收费、服务好,大企业/金融/政府用
MySQL 开源免费、中小型网站主流,后被 Oracle 收购(有商业版/社区版)
MariaDB MySQL 作者另起炉灶,完全兼容 MySQL,开源
SQL Server 微软出品,只能跑 Windows
Access Office 自带,小型桌面数据库
SQLite 轻量测试用,不支持远程用户
PostgreSQL 开源强大,有赶超 MySQL 的趋势

三、非关系型数据库(NoSQL)

  • 适用:量大、关联少的数据(用户发的视频、日志);效率优先。
  • 常见:
    • Memcached:纯内存,断电丢数据,速度极快
    • Redis:支持持久化,功能更强(主流)
    • MongoDB:最接近关系型的 NoSQL
  • 很多网站会”关系型 + 非关系型”混用。

四、安装与基本操作(MariaDB)

四个操作单元:库 → 表 → 列(字段)→ 行(记录)

五、用户与授权

  • all = 所有增删改查权限;可细化为 select/update/delete。
  • '用户'@'主机':localhost 本机、% 任意 IP、网段通配符。
  • 密码以加密形式(MD5 等)存 mysql 库的 user 表;root 默认禁止远程登录(泄露太危险)。
  • 改密码:set password for 'root'@'localhost' = password('123');
  • 图形化客户端:Navicat 远程连接数据库,便于管理。

⭐ 重点:网站代码里能找到数据库连接地址/账号密码——渗透拿到 Web 服务器后,常靠它远程连数据库取数据(证明漏洞)。

六、重点速记

  • 数据库 = 存数据;DBMS = 管数据的软件;SQL = 操作指令
  • 关系型(RDBMS):表格、有关联,MySQL/MariaDB/Oracle/SQL Server
  • 非关系型(NoSQL):量大关联少、效率高,Redis/MongoDB/Memcached
  • 操作单元:库→表→列→行;库在磁盘上就是文件夹
  • 授权 grant all on 库.* to 用户@主机;root 别开远程
  • 网站 = 代码 + 数据库;SQL 注入就是打数据库

自测题

  1. 为什么网站不用记事本存数据?
  2. 关系型和非关系型数据库的区别?
  3. Oracle 和 MySQL 的区别?
  4. MariaDB 和 MySQL 什么关系?
  5. 查看所有库、切换库、查看表的命令?
  6. grant 授权的语法是什么?
  7. 为什么 root 不允许远程登录?
  8. SQL 语句是给谁执行的?
参考答案 1. 打开慢、不能精准取数据、不支持高并发。
2. 关系型存关联数据(表格),非关系型存量大但关联少的数据,效率高。
3. Oracle 收费服务好,MySQL 开源免费。
4. MySQL 作者另开发的开源版本,操作完全兼容。
5. show databases;use 库名;show tables。
6. grant all on 库.* to '用户'@'主机' identified by '密码';。
7. 密码泄露后整个数据库会被拖走或删掉。
8. 数据库服务端(DBMS)。
