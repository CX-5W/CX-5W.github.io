PHP 数据库与会话操作

⭐ 一句话总结:PHP 通过 mysqli 连 MySQL 查数据,用 Cookie/Session 记录”你是谁”;登录认证是理解越权、身份伪造、会话劫持等漏洞的基础。

学习目标

  • 会用 PHP 连接 MySQL 并执行增删改查
  • 分清 $_GET / $_POST / $_REQUEST
  • 用 Cookie 做登录状态记录并知道其明文风险
  • 用 Session 做登录认证并理解”令牌”机制
  • 会使用 Cookie 编辑器插件辅助渗透测试

一、MySQL 基础准备

  • 常用函数:NOW()/CURRENT_TIMESTAMP 取当前时间;SELECT USER() 查看当前用户。
  • 中文乱码问题较多,初学先别插中文,或用 utf8mb4。

二、PHP 连接与查询

  • mysqli_fetch_assoc() 一行一行取出结果,配合 while 遍历全部记录。
  • 代码里写 SQL 可以不加分号(加了也不影响)。
  • 查询结果用 var_dump 看是 object,其中 num_rows 表示查到几行,可用于登录判断。

三、登录查询与超全局变量

变量 取哪里的数据 特点
$_GET URL 查询串 数据在地址栏可见,不安全
$_POST 请求体 地址栏看不到,更安全
$_REQUEST GET+POST+Cookie 万能但不安全,别用
  • 表单用 GET 提交,密码会出现在地址栏。
  • 表单 action 建议写 /xxx/login.php(以 / 开头),否则浏览器会拼接当前路径导致 404。

四、Cookie 登录认证

流程:

  • Cookie 在响应头里(Set-Cookie),浏览器下次请求放在请求头 Cookie 里。
  • Cookie 是明文存储在客户端的,用户名/密码/登录状态都能被 F12 看到。
  • 没登录访问受保护页面 → 弹窗提示”请先登录”并用 location.href 跳转登录页。
  • 登录成功后应跳回首页,首页根据登录状态决定是否显示”登录”按钮。
  • 渗透测试技巧:拿到别人的 Cookie 后,用 Cookie 编辑器(如 Firefox Cookie Editor、Chrome Modify Header)直接添加 Cookie,就能以对方身份访问受保护页面。
  • 清除 Cookie:浏览器清除浏览数据(ctrl+shift+delete)。

五、Session 会话机制

  • Session 把登录数据存在服务端,只给客户端一个随机”令牌”字符串(PHP 默认叫 PHPSESSID)。
  • 客户端看不到用户名/密码等真实数据,比 Cookie 安全一些。
  • PHP 默认把 Session 存到文件:session.save_path(如 phpstudy 的 tmp 目录);文件里存的是 username、login_status 等。
  • 登录成功前也会生成空 Session 文件;登录成功后才写入数据。
  • 每个用户一个 Session,服务端想存多少数据都行(受磁盘限制)。
  • 令牌丢失 = 身份丢失:拿到 PHPSESSID 同样能以对方身份登录(会话劫持),所以 Session 也不是绝对安全。

六、为什么要给未登录用户先发 Cookie

  • 大网站(如百度)访问首页就给一堆 Cookie,是为了识别”你确实访问过我的页面”。
  • 程序直接带用户名密码请求登录接口时,没有前置页面 Cookie,会被判定为非法请求。
  • 这是防自动化攻击的一种校验手段(部分高安全网站才做)。

七、重点速记

  • mysqli_connect 连接、mysqli_query 执行、mysqli_fetch_assoc 取行、mysqli_close 关闭
  • 字符串查询条件要加引号,外层双引号变量可解析
  • GET 数据在地址栏、POST 在请求体、REQUEST 万能但不安全
  • Cookie:setcookie / $_COOKIE,明文,浏览器自动携带
  • Session:session_start / $_SESSION,数据在服务端,令牌 PHPSESSID
  • 令牌丢失 = 身份被别人冒用

自测题

  1. mysqli_connect 常用参数有哪些?
  2. mysqli_fetch_assoc 的作用?
  3. $_GET、$_POST、$_REQUEST 的区别?
  4. 表单 GET 提交密码有什么风险?
  5. setcookie 后 Cookie 存在哪里?
  6. Session 和 Cookie 的本质区别?
  7. session_start 的作用?
  8. 拿到别人的 PHPSESSID 为什么危险?
参考答案 1. 主机、用户名、密码、数据库名、端口。
2. 从结果集中取出一行数组,配合 while 遍历所有记录。
3. GET 取地址栏参数,POST 取请求体,REQUEST 两者都能取但不安全。
4. 密码会显示在地址栏,容易被偷看和记录。
5. 存储在客户端浏览器(明文)。
6. Cookie 数据存客户端,Session 数据存服务端,客户端只有令牌。
7. 开启 Session 功能,才能使用 $_SESSION 存取数据。
8. 拿到令牌就能冒充对方身份登录,这叫会话劫持。
