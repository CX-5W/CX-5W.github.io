Nginx 进阶配置

⭐ 一句话总结:一个 Nginx 能跑 N 个网站(端口/IP/域名三种玩法);日志、SSL、跳转、压缩、访问控制、目录浏览都是安全运维必会配置——渗透测试先看的就是这些配置。

学习目标

  • 会用多端口/多 IP/多域名部署多个站点
  • 会用 include 拆分站点配置
  • 会配访问日志、basic 认证、SSL 证书
  • 会配 HTTP→HTTPS 跳转(return/rewrite)、gzip 压缩
  • 理解目录浏览、访问控制、location 优先级

一、一个 Nginx 部署多个站点

1. 多端口

复制多个 server{},每个用不同 listen(80/81/82)+ 不同 root(站点根目录),charset utf-8 解决中文乱码。

2. 多 IP

  • 给网卡配多个 IP(Linux:IPADDR1/2/3 写在 ifcfg 文件),每个 server 用 listen 192.168.61.139:80 绑定不同 IP,共用 80 端口。
  • 缺点:公网 IP 要花钱买。

3. 多域名(最常用)

  • 一个公网 IP + 多个域名即可;本地实验改 C:\Windows\System32\drivers\etc\hosts 把域名指向服务器 IP。
  • 多个 server 可用 default_server 指定”兜底网站”(访问不匹配的域名时展示)。

二、include 拆分配置

  • 每个站点一个独立 conf 文件(如 a.jadon.com.conf),管理方便、不易误删。
  • 停用某站点:把文件名后缀改成非 .conf(如 .stop)即可,不用删文件。

三、日志配置

  • 访问日志:/var/log/nginx/access.log;错误日志:error.log(按天切割)。
  • 网络安全法要求:日志保留不少于 6 个月,用于攻击溯源(根据 IP 追查攻击者)。
  • 自定义格式:log_format jadon '$time_local $remote_addr "$request" $status $body_bytes_sent'; 再在站点里 access_log /opt/nginx/a.log jadon;。
  • 常用变量:remote_addr(客户端 IP)、time_local(时间)、request(请求行)、status(状态码)、body_bytes_sent(响应大小)、http_referer(来源)、http_user_agent(浏览器)。
  • 注意:网页一刷新会请求图片/CSS/JS 等大量资源,所以日志很多行;日志目录要给 nginx 用户权限(chown nginx)。

四、basic 认证(给网站加锁)

  • 密码文件可在线生成 htpasswd 内容;适合保护后台等敏感路径。

五、SSL 证书(HTTPS)

  1. 买域名 → 阿里云/腾讯云申请(免费)SSL 证书 → 下载 Nginx 版。
  2. 解压得到两个文件:.pem(证书)+ .key(私钥),放到 /opt/cert/。
  3. 站点配置:
  1. 访问 https://域名 出现小锁 = 成功。

⭐ 重点:HTTP 明文(抓包可见)、HTTPS 加密(TLS,抓包只有密文);渗透中抓包看到明文数据就是没上 HTTPS 的站点。

六、跳转:return 与 rewrite

需求:用户访问 HTTP 时自动跳到 HTTPS,并保留原路径。

  • return 新写法,简单;rewrite 旧写法,要写正则:rewrite ^(.*)$ https://www.jadon.com$1 redirect。
  • 浏览器行为:收到 302(临时)/301(永久)响应头里的 Location 后自动再请求新地址(可抓包/curl -v 看到)。
  • 可再配一个不带 www 的 server 同样跳转。

七、gzip 压缩

  • 好处:省流量、传输更快(页面总资源 1.3M → 传输 986K)。
  • 图片/视频本身已压缩,再压没意义。
  • 响应头 Content-Encoding: gzip 告诉浏览器解压;浏览器请求头 Accept-Encoding: gzip 表示支持。

八、目录浏览与访问控制

  • 四层控制:防火墙(firewalld rich rule)封 IP,所有协议全断;七层控制:nginx 只影响网站。
  • 403 的三种常见原因:站点目录无 index.html、nginx 用户无读取权限(权限 000)、被 deny。

九、location 与优先级

  • 多个 location 可对不同路径做不同控制(如某个目录加 basic 认证、禁止 .txt 访问)。
  • 优先级:精准 = > ^~ > 正则(~/~*) > 通用 /。

十、重点速记

  • 多站点:多端口/多 IP/多域名;多域名最常用,hosts 文件本地测试
  • include conf.d/*.conf 拆分管理;停用改后缀
  • 日志保留 6 个月防溯源;log_format 自定义
  • HTTPS:443 + ssl_certificate(.pem)+ key;HTTP 明文、HTTPS 密文
  • 跳转 return 301 + $request_uri;gzip 压缩文本类
  • deny/allow 访问控制;403 = 无 index/无权限/被禁
  • location 优先级:= > ^~ > ~* ~ > /

自测题

  1. 三种多站点部署方式是什么?最常用哪个?
  2. include 有什么好处?怎么停用某个站点配置?
  3. 日志为什么要保留 6 个月以上?
  4. HTTPS 用哪个端口?SSL 证书两个文件分别是什么?
  5. return 301 后面的 $request_uri 起什么作用?
  6. gzip 一般压缩哪些类型文件?为什么不压图片?
  7. 网站返回 403 可能是什么原因?
  8. location 的优先级顺序是什么?
参考答案 1. 多端口、多 IP、多域名;多域名最常用(一个公网 IP 多个域名)。
2. 每个站点一个 conf 文件,好管理;把后缀改成非 conf(如 .stop)。
3. 网络安全法要求,方便攻击溯源。
4. 443;.pem 证书文件和 .key 私钥文件。
5. 跳转时保留用户访问的原始路径,不会回到首页。
6. 文本类(html/css/js/xml);图片视频本身已压缩,再压没意义。
7. 目录没有 index.html、nginx 用户没读取权限、IP 被 deny。
8. = 精准 > ^~ 前缀 > ~ ~* 正则 > / 通用。
