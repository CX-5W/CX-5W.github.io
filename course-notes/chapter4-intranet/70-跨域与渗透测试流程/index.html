70 · 跨域与渗透测试流程

跨域与渗透测试流程

⭐ 一句话总结:跨域解决”不同源网站如何交换数据”;渗透测试流程则是”扫描→手工验证→报告→复测”,打点还要走”拿Shell→免杀→提权→权限维持→内网渗透”。

学习目标

  • 理解同源策略与跨域方式
  • 掌握渗透测试完整流程
  • 会写渗透测试报告

一、同源策略

  • 同源三要素:协议 + 域名 + 端口 全部相同。
  • 只要一项不同就是非同源,浏览器会拦截响应数据(请求能发出去)。
  • 目的:防止恶意网站盗取其他网站数据。

二、跨域方式

1. CORS

  • 服务端响应头加 Access-Control-Allow-Origin: 指定域名(或 *),浏览器放行。

2. 跨域标签

  • 五大标签默认跨域:script、img、link、iframe、a(href)。
  • 可用于加载外部 JS(配合存储型 XSS 做大段攻击代码)。

3. JSONP

  • 利用 <script src="接口?callback=函数名">,服务端返回 函数名(数据)。
  • 需双方约定回调函数名,定制性好。

三、渗透测试流程(常规)

  1. 漏洞扫描:AWVS/AppScan/Xray(Web),Nessus(系统)。
  2. 手工验证:
    • 验证扫描器报出的漏洞(注入/XSS 等)
    • 主动挖掘逻辑漏洞、越权、未授权访问(扫描器扫不出)
  3. 出报告:漏洞名称、URL、数据包、证据截图、修复建议。
  4. 复测:标记已修复/未修复。

四、打点流程(攻击)

五、手工验证细节

  • 先检测/绕过 WAF;前端/后端过滤都要考虑。
  • 工具优先:sqlmap(可 –tamper 过 WAF),不行再手工。
  • 回显情况:有回显直接取数;无回显用报错注入/盲注/DNSlog。
  • 注入利用:
    • 读数据(库/表/密码)
    • getshell:三个前提——into outfile 可用、知道网站代码目录、目录有写权限。

六、参数化查询(PDO 预处理)

  • 把用户输入整体当作值查询,不当作 SQL 语句执行 → 注入失效。
  • 这是 SQL 注入”绝对防御”,发现后无需再测该点。

七、拿 Shell 姿势

  • 文件上传(最直观)
  • SQL 注入 into outfile 写一句话木马
  • 系统/中间件漏洞
  • 一句话木马:<?php @eval($_POST['x']);?>

八、报告要点

  • 漏洞名称、级别、URL、数据包、复现 payload、证据截图、修复建议。
  • 报告模板:风险评估、渗透测试报告、复测报告。

九、重点速记

  • 同源:协议+域名+端口
  • 跨域:CORS 响应头、五大标签、JSONP
  • 流程:扫描→验证→报告→复测
  • 打点:拿Shell→免杀→提权→维持→内网
  • 注入利用前提:into outfile+目录路径+写权限
  • 参数化查询防注入
  • 报告要有证据截图和修复建议

自测题

  1. 同源三要素是什么?
  2. 浏览器同源机制拦截的是什么?
  3. 跨域有哪几种方式?
  4. CORS 怎么实现?
  5. 渗透测试完整流程?
  6. 为什么逻辑漏洞要手工挖?
  7. SQL 注入 getshell 的三个前提?
  8. 参数化查询为什么防注入?
  9. 无回显时怎么注入?
  10. 渗透测试报告要包含什么?
参考答案 1. 协议、域名、端口。
2. 响应数据(请求能发出去)。
3. CORS、跨域标签、JSONP。
4. 响应头加Access-Control-Allow-Origin。
5. 扫描→手工验证→报告→复测。
6. 逻辑/越权是程序员逻辑缺陷,扫描器无法分析。
7. into outfile可用、知道代码目录、目录可写。
8. 输入被当成值而不是SQL语句执行。
9. 报错注入、盲注、DNSlog外带。
10. 漏洞名称、URL、数据包、截图、修复建议。
