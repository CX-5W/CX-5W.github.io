域渗透(口令传递与票据攻击)

⭐ 一句话总结:域渗透的三种传递手法是 PTH(哈希)、PTK(密钥)、PTT(票据);NTLM 用”质询-响应”校验,哈希就能代替密码登录;Kerberos 用票据做单点认证,伪造 TGT 就是黄金票据(通票),伪造 ST 就是白银票据(单服务票),配合 mimikatz 即可打穿整个域。

学习目标

  • 理解 Windows 本地登录与 NTLM 认证流程
  • 掌握 PTH/PTK/PTT 三种传递攻击
  • 理解 Kerberos 认证与 TGT/ST 票据
  • 掌握黄金票据、白银票据的伪造条件与用途

一、Windows 认证基础

本地登录认证

  • SAM 中只存密文哈希,内存中不留明文。
  • 本地登录、远程桌面输入密码都属于本地认证。

NTLM 认证(工作组/网络访问)

凡是在网络上访问共享资源,都会走 NTLM”质询-响应”流程,三个消息:

消息 名称 内容
Type 1 协商 客户端支持/请求的协议版本与功能列表
Type 2 质询 服务端产生 16 字节随机数 Challenge
Type 3 响应 客户端用 NTLM 哈希加密 Challenge 得到 Response,连同用户名返回

服务端用自己 SAM 里存的哈希加密同一个 Challenge,和 Response 对比,相同即通过。全程无明文密码传输。

域环境认证

  • 域用户信息存在 DC 上,成员机没有。
  • 域用户访问资源时,成员机通过 netlogon 协议与 DC 建立安全通道,把 Type 1/2/3 转发给 DC 认证。
  • 域里默认同时存在 NTLM 与 Kerberos 两种认证;Kerberos 异常时自动回退到 NTLM。

二、三种传递攻击(PTH/PTK/PTT)

攻击 全称 利用凭据 针对协议
PTH Pass the Hash NTLM 哈希 NTLM
PTK Pass the Key AES256-HMAC(K 值) NTLM(打了补丁的系统)
PTT Pass the Ticket 票据(TGT/ST) Kerberos

PTH 示例(mimikatz)

  • 会弹出一个新窗口,只有在这个窗口内可以用 net use \\192.168.241.21\c$ 直接访问目标(如域控)资源。
  • 工具包:微软自带工具(知道明文时用);impacket(psexec/wmiexec/secretsdump)支持哈希传递。

RDP 哈希传递

  • 依赖远程桌面的 Restricted Admin(受限制管理员) 特性。
  • Win7 需手动开启,Win8/2012R2 默认开启;老系统需装补丁。
  • 相关 RDP 漏洞:MS12-020、CVE-2019-0708(BlueKeep)。

三、Kerberos 认证流程

角色与名词

名词 说明
KDC 密钥分发中心,运行在 DC 上
AS 身份验证服务,验证用户身份并签发 TGT
TGS 票据发放服务,用 TGT 换服务票据(ST)
TGT 黄金票据,类似”游乐园通票”
ST/TGS 票据 白银票据,只能访问某一个服务
SPN 服务主体名称,注册在 AD 中,用于定位服务
krbtgt DC 内置账户,TGT 用它加密,哈希固定

认证流程

票据缓存默认约 10 小时;期间拿到主机就能直接提取、注入他人缓存的票据。

四、黄金票据与白银票据

黄金票据(TGT)

  • 伪造 TGT,像”通票”:可向 TGS 申请访问任意服务/任意主机的票据,连域控都能访问。
  • 伪造条件:krbtgt 的哈希值 + 域 SID(条件苛刻)。

白银票据(ST/TGS 票据)

  • 伪造某个服务的 ST,只能访问单个服务(如 CIFS 文件服务)。
  • 伪造条件:域名、客户端 SID、目标服务器计算机全名、目标服务器某用户(常用 administrator)哈希、服务名称、要伪装的用户名。
  • mimikatz 的 kerberos::golden 功能同样能生成白银票据;默认有效期较短(示例约 20 分钟),过期可再伪造。

  • 生成 TGT 票据 → 清除旧票据 → kerberos::ptt 导入 → dir \\DC域名\c$ 直接访问域控。

六、票据攻击的定位

  • 权限维持:即使域控被清理,只要留有 krbtgt 哈希,仍可随时伪造黄金票据重新掌控域。
  • 利用缓存票据:拿下主机后检查未过期(10 小时内)的票据,导出、注入直接使用,但靠运气。
  • 常用工具:mimikatz、impacket、kekeo、CS + ladon 插件(集成信息收集、PTH/PTT、漏洞扫描)。

七、重点速记

  • 本地登录查 SAM;网络访问走 NTLM 质询-响应;域用户认证经 DC/netlogon
  • PTH 用哈希、PTK 用 AES256 密钥、PTT 用票据
  • mimikatz:sekurlsa::logonpasswords 抓凭据,sekurlsa::pth 传递,kerberos::ptt 注入票据
  • RDP 哈希传递依赖 Restricted Admin,版本有限制
  • Kerberos 三角色:KDC/AS/TGS;时间戳防重放(约 5 分钟);票据缓存 10 小时
  • TGT=黄金票据=通票;ST=白银票据=单服务票
  • 伪造黄金票据要 krbtgt 哈希+SID;白银票据要目标服务用户哈希+SID 等
  • MS14-068 打补丁 KB3011780;票据攻击常用于权限维持

参考答案 1. 输入密码 → winlogon 接收 → lsass 哈希比对 SAM 数据库。
2. Type1 协商、Type2 质询(Challenge)、Type3 响应(用哈希加密 Challenge)。
3. 在域控 DC 上认证,成员机通过 netlogon 把认证数据转发给 DC。
4. PTH 用 NTLM 哈希,PTK 用 AES256-HMAC 密钥,PTT 用 Kerberos 票据。
5. sekurlsa::pth /user:xxx /domain:xxx /ntlm:哈希。
6. Restricted Admin 受限制管理员特性;Win8 和 2012R2 默认开启。
7. KDC 密钥分发中心(在 DC),AS 身份验证服务, TGS 票据发放服务,TGT 黄金票据,ST 白银票据。
8. 防中间人篡改和重放爆破,时间戳有效约 5 分钟。
9. 黄金票据是 TGT 通票可访问任意服务;白银票据是 ST 只能访问单个服务。
10. krbtgt 用户的哈希值和域 SID。
11. 域名、客户端 SID、目标服务器计算机全名、目标服务用户哈希、服务名称、伪装用户名。
12. KB3011780;需要域成员用户名、域名、密码、SID、域控 IP。
13. klist 查看,klist purge 清除。
14. 权限维持:被清理后仍可伪造票据重新控制域。
