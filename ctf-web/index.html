one


用burpsuite

拿到页面后，我看到是一个登录页面，用户名固定为 admin，要输密码。这种前端做的登录校验，密码一定是暴露在前端代码里的——因为后端没参与校验。

看到数据我们因该先看script

往下翻，看到 script 标签里的核心逻辑：
const correctPassword = “Q1RGe2Vhc3lfYmFzZTY0fQ==”;
const enteredPassword = document.getElementById(‘password’).value;

if (btoa(enteredPassword) === correctPassword) {
messageElement.textContent = “Login successful! Flag: “+enteredPassword;
}

关键信息：

把输入的密码做 btoa()（浏览器里的 Base64 编码函数）
和 correctPassword 比对
如果相等，就把输入的原文显示为 flag

看到 Q1RGe2Vhc3lfYmFzZTY0fQ== —— 以 == 结尾，只含字母数字和 +/= 字符，这明显是 Base64 编码。

核心套路总结
下次遇到类似前端登录的 CTF 题：

步骤 做什么
① 看页面源码（F12 或 curl）
② 找 script 里的登录逻辑
③ 寻找硬编码的密码 / token / 密文
④ 识别编码/加密方式（Base64、hex、rot13、AES 等）
⑤ 解码/解密，得到原文
前端校验的题通常就是找藏在 JS 里的密文 → 解码，因为前端没有秘密，所有代码和数据都是用户能看到的。

two


本题与上一题的区别
先看代码对比：

上一题（纯前端校验）
const correctPassword = “Q1RGe2Vhc3lfYmFzZTY0fQ==”;
if (btoa(enteredPassword) === correctPassword) {
// 直接在前端显示 flag
}

这一题（前端校验 + 后端提交）
const correctPassword = “Q1RGe2Vhc3lfYmFzZTY0fQ==”;
if (btoa(enteredPassword) !== correctPassword) {
e.preventDefault(); // ❌ 密码不对就阻止表单提交
}
// 密码对了 → 不阻止提交，表单正常发到 check.php

而且表单是：
form id=”loginForm” action=”check.php” method=”POST”

不使用bp的时候

在你还没输密码之前，我们先看看页面里藏了什么。

按 F12（或者右键 → 检查），在弹出的开发者工具里：

点 Sources（源代码）标签
左侧找到当前 URL 的页面，点一下
中间就看到 HTML 源码了
往下翻，找到 scrips 部分，你会看到这段代码：
const correctPassword = “Q1RGe2Vhc3lfYmFzZTY0fQ==”;
const enteredPassword = document.getElementById(‘password’).value;
if (btoa(enteredPassword) !== correctPassword) {
e.preventDefault();
}

这就是题目给的第一条线索。

识别编码

看到这段代码，你要问自己三个问题：

Q1: Q1RGe2Vhc3lfYmFzZTY0fQ== 是什么？

我教你怎么认：

它只由 大写字母、小写字母、数字 和 +、/、= 组成
以 == 结尾
没有汉字、没有空格
这 100% 是 Base64 编码。CTF 里最常见的编码之一。

解码 Base64

不用装任何工具，在你刚才的开发者工具里：

点 Console（控制台）标签
输入下面这行，按回车：
atob(“Q1RGe2Vhc3lfYmFzZTY0fQ==”)

分析前端做了什么事（关键）

再看一遍代码逻辑：
if (btoa(enteredPassword) !== correctPassword) {
e.preventDefault(); // 密码不对 → 不让表单提交到服务器
}
翻译成人话：

btoa() = 把输入的文字转成 Base64
如果输入的密码的 Base64 不等于 Q1RGe2Vhc3lfYmFzZTY0fQ== → 阻止提交
如果等于 → 放行，提交到服务器
所以密码就是 CTF{easy_base64} 本身。

打开拦截，准备改包

现在我们要让密码通过前端的检查，但拦截下来改请求头。

回到 Burp Suite：

Proxy → Intercept 标签
点一下 Intercept is off，让它变成 Intercept is on（红色）
这时候 Burp 会拦截所有经过代理的请求

在浏览器里登录

回到浏览器页面：

密码框输入：CTF{easy_base64}
点 Login 按钮
Burp 会弹出拦截到的请求，像这样：

POST /check.php HTTP/1.1
Host: 7b661535-cc69-42dd-b3fe-564b47ab6e40.challenge.ctf.show
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 …
Accept: text/html,application/xhtml+xml,…
Content-Type: application/x-www-form-urlencoded

username=admin&password=CTF%7Beasy_base64%7D

改 User-Agent（最关键一步）


在 Burp 拦截到的请求里，找到这一行：
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 …

选中这整行，改成：
User-Agent: ctf-show-brower

改完后看起来像这样：
POST /check.php HTTP/1.1
Host: 7b661535-cc69-42dd-b3fe-564b47ab6e40.challenge.ctf.show
User-Agent: ctf-show-brower
Accept: text/html,…
Content-Type: application/x-www-form-urlencoded

username=admin&password=CTF%7Beasy_base64%7D

放行请求看结果

在 Burp 的 Intercept 页面，点 Forward 按钮。

然后 Burp 的 Proxy → HTTP History 里：

找到刚才的请求
点它，下面会显示 Response 标签
响应里就能看到：
Login successful! Flag: CTF{user_agent_inject_success}

总结：你学会了什么
技能 怎么用
识别 Base64 看到 字母+数字+/+= 组成的字符串，用 atob() 解码
分析前端 JS 看代码里是否阻止提交，判断密码是前端验证还是后端验证
Burp 抓包 打开 Intercept，浏览器操作时拦截请求
改请求头 在拦截的请求里直接编辑 User-Agent
放行 Forward 改完后点 Forward，看返回结果

服务端怎么检查的（想象成伪代码）
里大概有这么一段逻辑：
if ($_SERVER[‘HTTP_USER_AGENT’] !== “ctf-show-brower”) {
echo “Invalid User-Agent”;
exit;
}
也就是：

读请求里的 User-Agent 字段
如果不等于 “ctf-show-brower” → 拒绝
如果等于 → 继续执行，返回 flag

如果再遇到类似题
不管以后碰到要求改什么头，套路都一样：

服务端提示 你要改的请求头 Burp 里怎么改
“Invalid User-Agent” User-Agent 找到这行，替换值
“Invalid Referer” Referer 找到这行，替换值
“Invalid Cookie” Cookie 找到这行，替换值
“Invalid X-Forwarded-For” X-Forwarded-For 加一行新头
错误信息就是答案，它告诉你缺什么，你就补什么。

three

第 1 步：看页面 JS 代码

F12 看源码，找到这段 JS：

const correctPassword = “SXpVRlF4TTFVelJtdFNSazB3VTJ4U1UwNXFSWGRVVlZrOWNWYzU=”;

function validatePassword(input) {
let encoded = btoa(input); // ①
encoded = btoa(encoded + ‘xH7jK’).slice(3); // ②
encoded = btoa(encoded.split(‘’).reverse().join(‘’)); // ③
encoded = btoa(‘aB3’ + encoded + ‘qW9’).substr(2); // ④
return btoa(encoded) === correctPassword; // ⑤
}

第 2 步：理解这 5 步编码流程
输入 → ①Base64 → ②追加”xH7jK”再Base64→去前3字符
→ ③反转再Base64 → ④前后加壳再Base64→去前2字符
→ ⑤再Base64 → 和 correctPassword 比对

每一层都在做 Base64 编码 + 字符串裁剪/变换

第 3 步：从正确密码反向推导（关键！）

从最外层往内推：

第⑤步逆向： btoa(e4) === correctPassword
→ e4 = atob(correctPassword)
→ e4 = IzUFQxM1UzRmtSRk0wU2xSU05qRXdUVVk9cVc5

第④步逆向： e4 = btoa(‘aB3’ + e3 + ‘qW9’).substr(2)
→ 补全前2个字符（暴力尝试64×64=4096种组合）
→ 找到前缀 YU，解码得到 aB3PT13U3FkRFM0SlRSNjEwTUY=qW9
→ 提取 e3 = PT13U3FkRFM0SlRSNjEwTUY=

第③步逆向： e3 = btoa(reverse(e2))
→ 解码 e3 → 反转 → e2 = FM016RTJ4SDdqSw==

第②步逆向（最难）： e2 = btoa(e1 + ‘xH7jK’).slice(3)
→ 补全前3个字符（暴力尝试64³=262144种）
→ 但要加一个条件：e1 必须是合法 Base64（因为 e1 = btoa(input)）
→ 找到前缀 ZTB，解码得到 e1 = e0E3MzE2

第①步逆向： e1 = btoa(input) → input = atob(e1)
→ input = {A7316

第 4 步：用 Burp 提交
有了密码 {A7316，回到 Burp：

拦截登录请求
密码填 {A7316
改 User-Agent 为 ctf-show-brower
Forward → 拿到 flag

关键知识点
概念 说明
多层编码逆向 从最外层一层层往里推，每层都是一次编码变换
Base64 裁剪 .slice(3) 去掉前3字符后，需要暴力补全才可能解码
约束条件 逆向时要加”合法字符”约束来缩小搜索范围
这题比前两题复杂很多，核心思路就是从外到内一层层剥开，每次补充被裁掉的字符，直到还原出原始密码。
